# Local foreground bridge

This is a Simulator-development host service for one **newly companion-managed** Codex thread. It exposes completed user/assistant text, supported questions, answer outcomes and reconnect state. It is not a remote deployment or an iOS app.

Run the deterministic checks with `python3 -m unittest discover -s bridge -v`. `python3 bridge/launch_probe.py` runs a real isolated experiment, consumes Codex inference, creates disposable history entries and an amx TUI, then stops its owned runtime and trashes its private temporary/token directory. It never contacts the shared daemon or existing threads. History entries are intentionally retained.

For a persistent development process, supply an owned mode-0700 directory with:

- `upstream-token`: a fresh random capability token, owned mode-0600 regular file.
- `provenance.json`: owned mode-0600 JSON containing `server_pid`, literal `ws://127.0.0.1:<port>` `endpoint`, `thread_id` returned by that server's own `thread/start`, and `project` equal to `<directory>/project`.
- `project`: the disposable project directory. Start a harmless first turn before resuming: thread/start alone has no rollout in the exercised CLI.

Launch the separate server with `codex -c 'notify=[]' -c 'tui.notifications=false' app-server --listen ws://127.0.0.1:0 --ws-auth capability-token --ws-token-file <absolute-private-token-path>`. Remove inherited `AWESOMUX_AGENT_*`, `AWESOMUX_PANE_ID`, `AWESOMUX_SESSION_ID`, `ZMX_SESSION` and `ZMX_SESSION_PREFIX` and `MOSHI_*` from its subprocess environment. Disable external `notify` and terminal notifications per launch on both server and TUI. This affects disposable test processes only, not global configuration, plugins or safety hooks. Preserve other host configuration and credentials. Record the endpoint from this owned server's startup output. A provenance file is a local launcher contract, not protection against a malicious process running as the same user.

`python3 bridge/server.py --private-directory <directory> --endpoint <owned-endpoint> --thread <owned-thread>` validates that record before attachment, checks the thread's project read-only, and resumes with no policy/model overrides. The service creates `client.json` without overwriting existing files; it contains the chosen loopback HTTP endpoint and a separate ephemeral HTTP capability token. Keep both tokens local; do not put them in shell startup files, Git, URLs or command-line arguments.

GET `/v1/thread` and POST `/v1/answers` require `Authorization: Bearer <HTTP-token>`, no Origin header, and Host exactly `127.0.0.1:<port>`. POST additionally requires Content-Type exactly `application/json`, Content-Length and a body no larger than 64 KiB. Chunked transfer is rejected. Responses disable caching and request/traceback logging is suppressed.

Answer bodies have `control_id`, canonical UUID `operation_id`, and `answers` mapping exactly the displayed question IDs to `{"answers":["selected label"]}`. `confirm_uncertain: true` is additionally required for replay after an uncertain prior attempt. Optional other answers are accepted only when the question allows them; questions without options allow free text. Secret questions and approvals are read-only/unsupported. Never send an error response to unsupported upstream requests: it could consume a desktop approval.

An operation reserves its question before writing. Identical retries return its current outcome without another write. Conflicting payload reuse returns conflict; a different operation cannot submit the reserved control again. `submitted` means handed to the proxy, not accepted by Codex or proof that this client won. `resolved` means server resolution, also without winner attribution. Write failure/disconnect becomes `uncertain`; there is no automatic resend. Connection generations, random control IDs and immutable proxy envelopes prevent stale controls or queued writes crossing reconnects. A quiet connected session remains connected.

Snapshots show up to 200 completed text items (16 KiB each, truncation flagged), returned recent history only, freshness and disconnected state. They omit streaming deltas and nontext tools. Pending controls/outcomes are bounded; reaching capacity disables controls with an explicit error. State is process-local; restart rotates controls and tokens.

On shutdown the service stops only its owned proxy. The caller owns stopping the separately launched server and amx session, then using `trash` on the private directory (including tokens). The smoke runner performs those steps and reports uncertainty honestly if teardown fails. Signal cleanup is best effort; no SIGKILL cleanup guarantee is claimed.

Both the HTTP adapter and upstream app-server must remain authenticated. No unauthenticated Codex listener is permitted. The handshake gate checks missing/wrong tokens and correct-token browser Origin rejection before inference. Physical-phone connectivity, push/APNs, hook correlation, session creation UI, normal-session takeover and exact desktop prompt disabling are not implemented here.

## Wire response contract

GET success is HTTP 200 `application/json`. `ios/Fixtures/disconnected.json` and `pending.json` and `submitted.json` are normalized snapshots exported from the real BridgeState for Swift decoding tests (only volatile IDs/time normalized).

Snapshot keys: `thread_id` (string), `generation` (nullable random connection string), `connected` (bool), `updated_at` (JSON number, possibly fractional; decode Double, Unix seconds of last upstream state event, not a health lease), `messages` (array), `pending` (array), `operations` (object mapping lowercase UUID strings to outcome strings, such as {"00000000-0000-4000-8000-000000000001":"submitted"}; unknown outcome strings are read-only), `error` (nullable string), `unsupported_request` (bool) and `capabilities` (boolean keys `completed_text_only`, `recent_history_only`, `questions`, `approvals`, `secret_questions`). Every process/connection generation is random; any generation change invalidates controls, including after process restart. Earlier uncertain client operations then remain a non-actionable notice; do not carry them into a new generation.

Each message has `id`, `turn_id`, `role` (`user` or `assistant`), `text` and `truncated`. Each pending control has `control_id`, `questions`, `status`, and `prior_attempt_uncertain`. That last boolean is authoritative and requires explicit user confirmation before a new replay-control submission. Each question has `id`, `header`, `question`, optional/null `options` (label/description objects), and optional camelCase `isOther`/`isSecret`. Preserve those camelCase flags; other outer snapshot names use snake_case. This client slice chooses one nonempty trimmed answer per question (every question is required); there is no multi-select UI. Other/free text is sent as one string in the same `answers` array. No distinct "Other" sentinel is sent. Secret questions remain unsupported.

POST replies have `{"outcome":"..."}` or pre-parse/auth errors `{"error":"..."}`. Status/outcome mapping: 202 `submitted`, `submitting`, `uncertain`; 200 `resolved`; 409 `conflict`, `already_submitted`, `confirmation_required`; 404 `rejected`; 503 `disconnected`, `capacity`. 400 malformed request, 401 unauthorized, 403 forbidden and 413 body limit occur before a protocol action. `rejected`/`confirmation_required` occur before a new operation reservation; `conflict`/`already_submitted` never free the existing reservation. Unknown outcomes must remain non-actionable. Error strings never carry credentials/request details.

A successful snapshot may exceed a client receive cap: text bounds are characters and serialization/pending questions can expand it. The Simulator client deliberately fails closed with an oversized-state notice at 4 MiB, rather than claiming every bridge snapshot fits. This development limitation is not a reason to send answers from an undecoded cache. POST responses have a separate 64 KiB client cap.

## Prepared private foreground transport

The phone transport is implemented locally but has not been enabled or exercised on a physical device. `private_route.py` supports only the reviewed Tailscale 1.102.4 commit, a validated direct Mach-O executable (resolved symlinks, wrappers rejected), foreground Serve on an unused 8443 or 10000 listener, exact private hostname/port/target readback and scoped process teardown. It never uses background mode, Funnel, off, reset or full-configuration restoration. Unknown schemas and baseline changes fail closed. Existing background and other foreground mappings must compare unchanged.

`python3 bridge/launch_probe.py --preflight-private-https` is read-only and prints the selected private origin. The network trial requires separately authorized exact origin, then `--interactive --private-https --approved-private-origin <origin>`. That argument contains no key. The private `client.json` supplies endpoint/key for deliberate local phone entry; do not copy its key to chat, screenshots, URLs, launch arguments or source. The proxy accepts only the configured exact Host plus its loopback Host, retaining bearer authentication, no Origin and strict POST framing. Actual Serve Host/framing and physical TLS remain unverified.

The launcher records its foreground CLI child and starts a separate supervisor first, using inherited private pipes for readiness and parent liveness, with the same absolute 20-minute awake-host-time operational deadline. Launcher monitors supervisor; supervisor monitors parent EOF and child creation identity. Missing readiness stops the child before returning. Cleanup retires route before reusing backend ports and reads back preservation. The operational bound assumes one watcher survives after readiness. Simultaneous watcher death or unacknowledged startup can require operator cleanup; an orphan proxy can become risky if its backend TCP port is subsequently reused. Do not claim a guaranteed security timeout.

`test_private_route.py` uses invented configuration and fake CLI start/readback outcomes; `test_route_watchdog.py` uses disposable Python children for deadline, parent SIGKILL, supervisor SIGKILL, ignored TERM and readiness failure. These are independent of live Tailscale route validation. Darwin child creation timestamps use Apple's proc_bsdinfo API; https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_info.h describes its layout. Historical Simulator evidence remains separate from physical trial results.
